# Independent Applied Analytics Development Programme - Maxwell Pearson

This repository documents a structured, self-directed programme created to develop practical data analytics capability through technical study, independent problem-solving and project-based application.

The programme combines official documentation, structured courses, AI-assisted tutoring, guided technical exercises, independent reconstruction, quality assurance and realistic analytical projects.

Each stage produces documented evidence rather than relying solely on course completion. Deliverables include working files, code, validation results, screenshots, methodology notes and Git version history.

---

## About me

I am Max Pearson, a BSc Sport and Exercise Science student with a year in Data Analytics and AI at the University of Nottingham developing the technical and commercial skills required for data analyst roles.

My previous analytical experience includes working as a GPS Data Analyst Intern with the University of Nottingham Men’s Hockey 1st Team. In this role, I monitored athlete performance data during training and competition and communicated relevant findings to support performance decisions.

I designed this programme to extend on that experience into broader commercial, operational, healthcare and financial analytics before beginning my year in Data Analytics and AI.

---

## Programme purpose

The programme develops the complete analytical workflow:

1. Understanding the business or operational problem
2. Identifying suitable data and analytical questions
3. Cleaning and transforming source data
4. Validating data quality and calculation accuracy
5. Conducting descriptive and exploratory analysis
6. Developing interactive analytical outputs
7. Communicating findings, limitations and recommendations
8. Documenting and version-controlling the complete process

The objective is to demonstrate the ability to apply analytical tools to structured problems and produce reliable, explainable and auditable work.

## Learning methodology

| Method | Application |
|---|---|
| Official documentation | Understanding correct syntax, functionality and recommended practices |
| Structured courses | Establishing foundational knowledge and guided technical practice |
| AI-assisted tutoring | Clarifying concepts, generating practice questions, troubleshooting errors and reviewing work |
| Independent reconstruction | Rebuilding important formulas and processes without instructions |
| Project-based application | Applying technical skills to realistic datasets and business questions |
| Quality assurance | Testing outputs using reconciliation, uniqueness, completeness and error checks |
| Documentation | Recording methods, decisions, assumptions, limitations and outcomes |
| Version control | Using Git and GitHub to maintain a transparent development history |
| Iterative improvement | Identifying errors, implementing corrections and applying lessons to later work |

AI is used as a learning, planning and review tool rather than as a substitute for technical implementation. All formulas, transformations, queries, analysis and validation included in this repository are implemented, tested and understood before being included.

## Portfolio Project 1 — Private Healthcare Access Analytics

An operational analytics project for a fictional UK private-healthcare provider using entirely synthetic and non-identifiable data.

The project examines:

- Patient journeys from enquiry to treatment
- Appointment outcomes
- Enquiry-to-consultation waiting times
- Consultation-to-treatment waiting times
- Cancellations and non-attendance
- Clinic and service capacity
- Demand and utilisation patterns
- Opportunities to improve patient access

The project uses Python, BigQuery, Excel, Power Query and Power BI.

Deliverables include:

- Synthetic data generator
- Data dictionary and source documentation
- Validated analytical tables
- SQL query collection
- Excel scenario model
- Power BI dashboard
- Executive summary
- Privacy, bias and limitations statement

No genuine patient or identifiable healthcare information is used.

---

## Portfolio Project 2 — UK Consumer Finance Risk Intelligence

A financial and conduct-risk analytics project using public Financial Conduct Authority and Bank of England data.

The project examines:

- Complaint volumes and rates
- Product and firm-level patterns
- Changes and persistence over time
- Potential conduct-risk indicators
- Relevant economic context
- Areas requiring further investigation or remediation

The project uses PostgreSQL, Python, Tableau and Power BI.

Deliverables include:

- Source register and data documentation
- Clean relational data model
- SQL analysis
- Python validation and exploratory analysis
- Tableau trend dashboard
- Power BI executive report
- Conduct-risk summary
- Methodology and limitations statement

The analysis distinguishes descriptive patterns from causal conclusions and documents the limitations of the available data.

## Evidence standard

Each completed stage includes evidence appropriate to the work undertaken:

- A clearly defined objective
- A completed and accessible deliverable
- Documented formulas, queries or transformations
- Relevant screenshots
- Identified and attributed data sources
- Row-count and uniqueness checks
- Missing-value and date-boundary checks
- Reconciliation against known totals
- Error handling and invalid-input testing
- Methodology and implementation notes
- Git commits describing the work completed

Outputs are not accepted simply because they produce a result. Calculations and transformations must also be traceable, explainable and validated.

## Data sources and ethics

All external data sources are documented and attributed within the relevant project.

Foundational technical exercises use public sample datasets, including Microsoft’s Financial Sample workbook.

The private-healthcare project uses entirely synthetic data and does not contain genuine patient information or personally identifiable healthcare data.

The consumer-finance project uses public regulatory and economic data. Findings are presented as descriptive evidence unless the available data supports a stronger conclusion.

Data limitations, assumptions and analytical definitions are documented throughout the repository.

## Professional principles

The work in this repository is guided by the following principles:

- Accuracy before presentation
- Clear definitions before calculation
- Reconciliation before interpretation
- Reproducibility before completion
- Honest communication of assumptions and limitations
- Appropriate handling of sensitive subject areas
- Recommendations proportionate to the available evidence
